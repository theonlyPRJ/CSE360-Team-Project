## 1. Overview of Tasks 6 and 7

This document provides the complete requirements-to-tests tracking matrix and iterative testing notes produced in **Task 6**, which directly specify the Javadoc HTML files and source code screenshots contained in the `ContributorTests_Javadocs` folder for **Task 7** (Rubric 7.1 through 7.4):

- **Rubric 7.1 (2%):** Establishes all 12 TP2 Contributor requirements (`TP2-REQ-01` through `TP2-REQ-12`) derived from the Contributor User Stories (`US-HW2-01` through `US-HW2-04`) and TP3 Forward Compatibility Epics, mapping each requirement to its Javadoc HTML files and source code screenshots.
- **Rubric 7.2 (2%):** Provides 2 to 4 tests per requirement (28 semi-automated test cases in `ContributorTestingAutomation.java` and 5 interactive manual test procedures in `ContributorManualTestbed.java`, incorporating both positive and negative tests) documented in the generated Javadoc HTML files.
- **Rubric 7.3 (3%):** Documents inside every test's Javadoc comment: (1) which requirements are being tested, (2) how the code implements satisfaction of the requirements, and (3) how to interpret the console output to know whether the test passed or failed.
- **Rubric 7.4 (3%):** Captures the source code and internal comments for every test in a descriptively named PNG screenshot (`TC01_CreateValidLesson_Screenshot.png` through `TC28_RejectTP3HooksOnNonExistentId_Screenshot.png` and `Manual01` through `Manual05`) inside `ContributorTests_Javadocs/`.

## 2. Iterative Development & Testing Notes (Task 6)

1. **Iteration 1 — Entity & Collection Baseline Inspection:** Reviewed `entityClasses.LessonLearned` and `entityClasses.LessonLearnedList` in the TP2 repository. Confirmed that `LessonLearned` enforces title (4–64 chars), description (10–1000 chars), author, category, timestamp, and TP3 forward-compatibility attributes (`isFlagged`, `moderationNote`, `endorsementCount`, `isVerified`), while `LessonLearnedList` provides thread-safe in-memory CRUD and subset filtering (`allLessons` and `currentSubset`).
2. **Iteration 2 — Validation & Ownership Guard Extraction:** Created `guiContributor.ContributorValidator` to centralize pre-mutation field boundary validation (`validateTitle`, `validateDescription`, `validateCategory`, `validateAuthor`, `validateSearchKeyword`, `validateLessonFields`) and role-based ownership verification (`verifyModifyPermission`), ensuring negative tests return clear, context-relevant diagnostic messages before any collection or database mutation occurs.
3. **Iteration 3 — Semi-Automated & Manual Testbed Construction:** Modeled `testing.ContributorTestingAutomation` and `testing.ContributorManualTestbed` after the Foundations `PasswordEvaluationTestingAutomation` and `PasswordEvaluationTestbed` classes. Verified that all 28 automated test cases pass (`28 passed, 0 failed`) and generated clean Javadoc HTML files and source code screenshots.
